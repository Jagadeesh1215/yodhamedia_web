# YodhaMedia Web

YodhaMedia Web is a Next.js 14 app for a digital growth agency focused on hospitals, clinics, doctors, and service businesses.

The current codebase includes:

- A public marketing site with service pages, blog content, and lead capture
- A private admin area for blog management and lead review
- Server-side content storage backed by Prisma/Postgres, with seeded starter content and Cloudinary image URLs
- NextAuth-based admin authentication

## Stack

- Next.js App Router
- React 18
- TypeScript
- Tailwind CSS
- NextAuth
- Nodemailer
- Server-side Cloudinary image upload for blog cover images

## Project Structure

- `app/` - route segments, page entries, API routes, and layouts
- `components/` - shared UI, admin UI, forms, layout, and media helpers
- `lib/` - server helpers, Prisma client, content store, auth helpers, constants, and utilities
- `prisma/` - database schema and optional seed script
- `content/` - legacy seed assets and repo examples, not the live datastore
- `public/` - static assets
- `docs/` - architecture, API, data flow, admin, seed, and fallback docs

## Main Routes

- `/` - marketing homepage
- `/about` - agency overview
- `/services` and `/services/[slug]` - service catalog and detail pages
- `/blog` and `/blog/[slug]` - blog list and article pages
- `/contact` - contact form
- `/book-consultation` - consultation booking flow
- `/admin` - admin dashboard
- `/admin/blogs` - blog library
- `/admin/blogs/new` - create a new article
- `/admin/blogs/[slug]/edit` - edit an article
- `/admin/leads` - lead inbox
- `/not-found` - branded public 404 page
- `/admin/not-found` - branded admin 404 page

## Admin Workflow

The admin UI is styled as a dark blueprint-style workspace with a minimal palette:

- deep charcoal background
- muted gold accent
- hairline borders
- transparent panels
- monospace metadata labels

Reusable admin primitives live in `app/globals.css`:

- `.admin-scope`
- `.admin-shell`
- `.admin-panel`
- `.admin-panel-strong`
- `.admin-field`
- `.admin-chip`
- `.admin-kicker`

The admin layout is centralized in `app/admin/layout.tsx`, so the dashboard, blog library, editor, and lead inbox all share the same shell.

## Content and Data Flow

The app now uses Prisma as the repository layer:

- Blog posts are read and written through `lib/blog/store.ts`
- Blog content, including Cloudinary cover image URLs and public IDs, is stored in Postgres through Prisma
- Contact leads and consultation requests are stored in the database through Prisma

This keeps the app simple to run locally while still giving us proper relational storage in production.

## If You Want Postgres

The cleanest migration point is `lib/blog/store.ts`.

That file is the repository boundary for:

- blog post reads and writes
- contact lead storage
- consultation lead storage

If you provide a Postgres connection string, Prisma will handle the blog and lead persistence layer while keeping the admin routes and UI unchanged.

## Fallbacks And Empty States

- The public blog page shows a friendly empty state if no published articles
  are available.
- The site has branded public and admin `not-found` pages, plus a global
  `error.tsx` and admin-specific `error.tsx` for graceful failures.
- Seed blog posts are generated by `prisma/seed.cjs` so new clones have
  content immediately.

## Notes For Future Devs

- The admin UI is intentionally minimal and high-contrast. Do not reintroduce heavy card shadows or bright fills unless there is a clear UX reason.
- Blog editing is server-side, not a client CMS integration.
- Keep the public route shell separate from the admin shell so the marketing site and admin workspace can evolve independently.
- The database is the live source of truth. The `content/` directory is no
  longer used as a runtime datastore.
